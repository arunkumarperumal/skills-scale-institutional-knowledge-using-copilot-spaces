# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Docs. This folder and the linked documents provide the guidance, templates, and processes used to run successful projects at OctoAcme.

## Quick Start
New to OctoAcme projects? Start with the Project Management Overview: docs/octoacme-project-management-overview.md

## Our Approach
OctoAcme projects follow a consistent, lightweight approach designed to deliver customer value quickly while maintaining clarity and continuous improvement:

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments and iterate based on feedback
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead (PdM)
- **Data-informed decisions**: Define measurable success metrics and use data to guide choices
- **Psychological safety**: Encourage candid feedback and learning

## Quick Reference
- Key roles: Project Manager (PM), Product Manager (PdM), Developers, QA, Stakeholders
- Core artifacts: Project One-pager, Roadmap/Release Plan, Sprint Backlog, Definition of Done, Risk Register
- Communication cadence:
  - Daily standups (15 min) — focus on progress, blockers, dependencies
  - Weekly delivery sync — show progress and flagged risks
  - PM + PdM weekly alignment
  - Monthly stakeholder updates
  - Ad-hoc escalations as needed

## Getting Started
1. Read the [Project Management Overview](docs/octoacme-project-management-overview.md) to understand roles and lifecycle
2. For a new initiative, complete the [Project One-pager](docs/octoacme-project-initiation.md) and follow the Initiation checklist
3. Use the Project Planning doc to create backlog items with clear acceptance criteria and estimates
4. Follow the Execution & Tracking doc for PR workflow, CI checks, branch conventions, and release readiness
